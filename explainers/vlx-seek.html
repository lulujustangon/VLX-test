VLX-Seek 拆解

多数视觉语言模型要定位一个物体，得一位一位写出 [x1, y1, x2, y2]。VLX-Seek 换了做法：先找出一批候选区域，把每个区域编成一个 token 放进提示词，语言模型只需回答“是第几号区域”。下面用仓库自带的 demo 图把整条推理路径走一遍，每一步都对应到源码。

写坐标常规 VLM 的定位输出
98输出 token（估算）
报编号VLX-Seek 的定位输出
5输出 token

查询：orange（在下一节切换）。只计定位部分。坐标按 Qwen 系分词器“数字逐位切分”的规则估算：每个框 2 个括号、3 个逗号、3 个空格，再加上每一位数字。<objK> 是词表里的特殊 token，一个编号就是一个 token。

第 1 步
先找候选区域
候选框网络只负责“哪里可能有东西”，不判断是什么。

  

    
官方博客里的候选框网络（OPN）因公司政策没有开源，仓库用开源的 WeDetect-Base-Uni 代替（detect_tools/WeDetect/generate_proposal.py）。它是 YOLO-World 结构：ConvNeXt-B 主干、CSPRepBiFPAN 颈部、对比式检测头。分类用的不是固定类别，而是 256 个可学习的提示向量，所以它给出的是“像物体的区域”，与类别无关。

    
你也可以完全不用它：任何检测器的框、用户手画的框，只要是原图像素坐标 [x1, y1, x2, y2]，都能通过 --bbox-list 传进去。模型最多接受 100 个区域 token。

  

  

    

      输入先 letterbox 到 640 × 640
      

      
      
缩放比 r = min(640/500, 640/399) = 1.28，图像变成 640 × 511，上下各补约 64 像素灰边（RGB 114）。每个网格点是一个锚点，预测一个框。

    

    

      
8,400
三层特征图上的锚点：步长 8 / 16 / 32，对应 80×80 + 40×40 + 20×20 个格点，每点预测一个框（DFL 回归，reg_max = 16）。

      
2,150,400
每个锚点与 256 个提示向量逐一打分（sigmoid），得到 8,400 × 256 个分数。

      
≤ 30,000
filter_scores_and_topk：保留分数最高的 3 万个（锚点，提示向量）组合。

      
NMS 0.7
按提示向量分组做非极大值抑制，IoU 阈值 0.7，去掉重叠框。

      
100
取前 100 个框，减去填充、除以 1.28 还原到原图像素，裁到图内，丢掉无面积的框。这就是传给 VLX-Seek 的候选列表。

    

  






  
第 2 步
把每个框编码成一个区域 token
Hybrid Fine-Grained Region Encoder（HFRE）：两条视觉通路，各自在框里取特征，再合成一个向量。

  

    
框本身只是四个数字，模型还要知道框里是什么。HFRE 从两座视觉塔的特征图上把框“抠”出来：语义通路用主视觉塔 Qwen3.5-VL 的特征，和语言对齐得好；细节通路用辅助视觉塔 C-RADIOv4-SO400M，分辨率更高，保留边缘、纹理和小目标。选一个框看看它落在两张特征图的哪些格子上。

语义通路

      
主视觉塔 Qwen3.5-VL
图像先缩放到 32 的倍数（demo：512 × 384），切成 16 px 的 patch，再 2×2 合并 → 16 × 12 的特征图

      
↓

      
SimpleFP 金字塔（发布配置：开启）
×8 ×4 ×2 ×1 上采样，得到步长 4 / 8 / 16 / 32 的四层，每层 512 通道

      
↓

      
RoI Align 14×14 → 平均池化
框先按 512/500、384/399 缩放到这张图的坐标系；四层结果拼接 → 4 × 512 = 2048 维

    

    

      
细节通路

      
辅助视觉塔 C-RADIOv4-SO400M
原图直接输入，取整到 16 的倍数（demo：496 × 400），27 层、1152 维 → 31 × 25 的特征图

      
↓

      
取第 7 / 14 / 20 / 27 层（发布配置不走 SimpleFP）
四层都在步长 16 上，按通道拼接 → 4 × 1152 = 4608 维

      
↓

      
RoI Align 14×14 → 平均池化
在拼接后的特征图上做一次，比例 1/16

    

    

      
↓ ↓

      
融合：两路拼接（mm_object_feature_combination = concat），2048 + 4608 = 6656 维，等于 mm_object_hidden_size

      
加位置编码：把框换成归一化的 (cx, cy, w, h)，四个量各生成 1664 维（6656 的四分之一）的正弦编码，加到特征上。这一步让模型知道区域在图里的哪儿、有多大。

      
投影：mm_projector_aux 是 mlp2x_gelu：6656 → 4096 → 4096，正好是语言模型的隐层维度

      
得到 1 个向量，填进提示词里该区域 <objfeat> 的位置。每个框对应一对 token：<objK> 负责编号，<objfeat> 负责内容。

    

  

  
上面每个取值都来自发布权重的 config.json。源码里还有别的分支（只用一路、mean 融合、细节通路也走 SimpleFP），默认的 RoI 网格是 7×7，但发布的 10B 用的是 14×14 和上面这套组合。






  
第 3 步
拼成一条 token 序列
图像、区域、问题被排成一行，语言模型看到的就是这一行。

  

    
vlx_seek_worker.py 先拼出文本 prompt，再把占位符展开成真正的 token id，最后在模型里把这些位置的嵌入替换成视觉特征：

  

  

    

      img图像 token：id 248056，共 ≈192 个（16 × 12）
      obj区域编号 <objK>
      ▪区域特征 <objfeat>：id 248181
    


# 文本形式（9 个框、查询 orange）
<|im_start|>user
<|vision_start|><image><|vision_end|>
<obj0><objfeat><obj1><objfeat><obj2><objfeat> … <obj8><objfeat>
Detect all the instances of: orange.<|im_end|>
<|im_start|>assistant

# 展开后（_expand_multimodal_tokens）
<image>    → 248056 × (T·H·W / 4)   # demo：1 × 24 × 32 / 4 = 192
<objfeat>  → 248181                 # 每个框一个

# 模型 forward 里（modeling_vlx_seek_1_5.py）
inputs_embeds = embed(input_ids)
inputs_embeds = inputs_embeds.masked_scatter(image_mask, image_embeds)   # 换成主视觉塔特征
inputs_embeds[input_ids == 248181] = object_features                     # 换成 HFRE 区域特征

    
所以每个候选框在输入端占 2 个 token。100 个框也只多 200 个 token，和 192 个图像 token 同一量级。框的数量必须和 <objfeat> 的数量严格相等，否则 forward 会直接报错。

  

  

    
任务提示词来自 vlx_seek/task_templates.py，中英文各一套，每个模板只有一个 {} 槽位：

第 4 步
语言模型只输出编号，worker 再换回坐标
定位变成了在 9 个（最多 100 个）候选里做选择。

  

    
语言模型是 Qwen3.5 系的文本模型：32 层，其中 24 层线性注意力、8 层全注意力，隐层 4096（config.json）。线性注意力层用来降低推理和显存开销（README：“more Linear Attention layers”；装上 flash-linear-attention 和 causal-conv1d 才走快速内核）。它读完整条序列后，按固定格式生成：

  


<ground>orange</ground><objects><obj0><obj1><obj2><obj5><obj6></objects>

# worker 用正则把它拆开，再按编号查表拿回原始框
re.finditer(r"<ground>(.*?)</ground>\s*<objects>(.*?)</objects>", answer)
re.finditer(r"<obj(\d+)>", objects)   →   caller_boxes[K]

  

    
两个细节：

    
    
      
  • 输出的框就是输入的框。模型不改坐标，只做选择，所以框的精度完全取决于候选框本身。
    • 
      
  • 目标不存在时答 None。1.5 版用难负样本训练，并加了显式的 None 格式，让模型在没有匹配区域时拒答，而不是硬选一个框。
    • 
    

    
还有一层编号映射：发布的 config.json 设了 mm_bbox_order_mode = raster，所以 worker 会先按 (x1, y1) 给框重新排序再喂给模型（模型训练时见过的顺序），生成后再把 <objK> 换回你传入的编号。选一种排序看 demo 的 9 个框会怎么排：

  

  

  






  
为什么更快
输出 token 的账
解码是一个 token 一个 token 地生成，定位部分越短，延迟越低。

  

    
写一个框大约要 19 个 token（两三位数的坐标），而引用一个区域只要 1 个 token。目标越多，差距越大。下图按 demo 的框逐个计算：

  

  
  
灰色：写成 [x1, y1, x2, y2] 的估算；蓝色：VLX-Seek 的 <objK> 引用。目标不存在时两种写法都只需一个答复，这时 VLX-Seek 的收益在于不编造框，而不在 token 数。官方在 X 上报告过一次实测：两张 RTX 4090、基于 vLLM 的自定义实现，一张图检出 30 个目标，端到端 1.81 秒。






  
它是怎么训练出来的
两阶段：先学会“读”区域 token，再学会用它做各种感知任务。

  

    
阶段一
区域与语言对齐
主干 VLM 基本冻结，只训练 HFRE、区域投影器和新增的特殊 token，让每个 <objfeat> 向量落进语言模型能理解的空间。

    
阶段二
感知指令微调
加入检测、指代、区域描述、区域推理、计数、OCR 等指令数据；同时混入通用 VLM 数据防止遗忘，混入负样本教它答“没有”。

    
1.5 版新增
面向具身场景
扩充无人机、监控、机器人视角数据；换用更强的辅助视觉塔和 VLM 主干；更快的候选框管线；难负样本拒识训练与显式 None 格式。

  






  
代码地图
按推理顺序排列。

  

    
文件负责什么

    
      
inference.py命令行入口：读图；没给 --bbox-list 时调用 WeDetect 生成 100 个框；按任务调用 worker；把选中的框画到图上。

      
detect_tools/WeDetect/generate_proposal.py候选框网络：letterbox 640、ConvNeXt-B + CSPRepBiFPAN、256 个提示向量打分、NMS 0.7、取前 100。

      
vlx_seek_worker.py推理封装：校验并裁剪框、按 mm_bbox_order_mode 排序、拼 prompt、展开占位符、generate、把 <objK> 映回原编号和坐标。

      
vlx_seek/task_templates.py中英文任务模板。

      
…/vlx_seek_1_5/builder.py加载 tokenizer、模型，以及主、辅两个图像处理器。

      
…/language_model/modeling_vlx_seek_1_5.py模型主体：encode_images、encode_objects，把两类特征写进嵌入，再交给 Qwen3.5 文本模型。

      
…/omchat_arch.py装配两座视觉塔、图像投影器、HFRE 和区域投影器。

      
…/multimodal_encoder/qwen3_5_vl_encoder.py主视觉塔（语义通路），输出合并后的 token 和空间特征图。

      
…/multimodal_encoder/c_radio_v4_aux_encoder.py辅助视觉塔（细节通路），按 1/4、2/4、3/4、末层取 4 个中间层。

      
…/multimodal_visual_prompt_encoder/hybrid_finegrained_region_encoder.pyHFRE：RoI Align、池化、两路融合、正弦位置编码。

      
…/multimodal_visual_prompt_encoder/simple_fpn.pySimpleFP：从单层 ViT 特征造多尺度金字塔（ViTDet 的做法）。

      
…/multimodal_projector/builder.py图像投影器与区域投影器（linear 或 mlpNx_gelu）。

      
…/constants.py特殊 token 与 id：<|image_pad|> 248056、<objfeat> 248181。

    
  






  
用之前要知道的

  

    
    
      
  • 召回上限在候选框。候选框网络漏掉的物体，语言模型没有编号可选；框画得不准，输出也就不准。
    • 
      
  • 最多 100 个区域。场景里物体更多时要分块或换候选策略。
    • 
      
  • 开源版的候选框网络不是博客里的那个。仓库用 WeDetect-Base-Uni 代替内部 OPN，效果可能和博客里的数字不同。
    • 
      
  • 效果数字来自作者自己的评测。例如 1.5 博客报告 10B 在 COCO 上 F1@IoU 均值 58.9，在 VisDrone 上幻觉率 FP/GT 为 7.0。
    • 
      
  • 本页的框和答案是示意。框按 demo 图目测放置，选中结果是正确答案而不是实测输出；图像 token 数按 patch 16、2×2 合并推算。
